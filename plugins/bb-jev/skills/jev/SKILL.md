- Перед правками в крупной задаче вызови `jev_check_plan`. Передай требования и план с проверками.
- Перед коммитом или PR вызови `jev_acceptance`, если задача требует отдельной приёмки. Передай критерии, относящиеся к ним части диффа и фактический вывод проверок.
- При исследовании вызови `jev_fact_check` для существенного спорного утверждения. Передай одно утверждение, точные цитаты и ссылки или пути к прочитанным источникам.
- Пропускай Jev для мелких правок и обычного чтения файлов. Вердикт дополняет проверки проекта. При `failed` или `inconclusive` сопоставь вердикт с первоисточником и прогонами. При `unavailable` продолжай обычную проверку.

С ключом переданные поля уходят в TypeSafe AI. Передавай только необходимые фрагменты, которые разрешено передать сервису, без ключей и данных заказчика. Ключ задаётся в настройках плагина Jev или в окружении сервера bb через `TYPESAFE_API_KEY`. `bb jev status` показывает наличие ключа, статистику текущего треда при запуске из него и общую статистику. Оценка расхода учитывает запросы, для которых API вернул число входных токенов.

Плашка Jev в **Provider Usage → All** показывает оценку остатка от последнего введённого баланса. Чтобы её настроить или обновить после пополнения, возьми **Available credits** из TypeSafe **Settings → Billing** и выполни `bb jev balance set <USD>`, например `bb jev balance set 10.00`. Из этой суммы вычитается расход Jev в данном bb после ввода. Расходы вне этого bb и пополнения нужно сверять в TypeSafe Billing.

## Связанная проверка для Арены

Когда прогон явно включает связанную проверку, используй `jev_review_requirements`, `jev_review_plan` и `jev_review_acceptance` вместо отдельных проверок плана и приёмки. В первой передай постановку и список требований с ID `R1`, `R2` и т. д. Во второй свяжи каждый шаг с ID требований и приложи `reviewId` сверки требований. Для приёмки передай `reviewId` сверки плана, отпечаток проверенной ревизии, дифф и фактический вывод тестов. Передавай только разрешённые к отправке материалы.

`jev_review_status` сравнивает отпечаток сохранённой приёмки с текущим, который передал вызывающий. После изменения кода новая приёмка должна использовать новый отпечаток и актуальный вывод запуска.
