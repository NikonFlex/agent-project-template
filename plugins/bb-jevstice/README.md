# Jevstice в BB

Исходный Jevstice [v2.4.0](https://github.com/veschin/jevstice/tree/a38481a75b35cffb1b6c0d5911c8afe6fe0bdb38)
закреплён коммитом и контрольной суммой архива в lock-файле. В архив входят исходники, документация,
тесты и Linux-супервизор. Лицензия — `LICENSE.jevstice`. Сборщик встраивает текст навыка и даёт
контроллеру читать артефакты через BB. Вопросы, схемы инструментов, вердикты и проверки остаются из
закреплённой версии.

Сначала установите [bb-jev из шаблона](../../docs/plugins.md) и укажите **TypeSafe API key**
в его настройках в BB. Для сборки Jevstice из корня шаблона нужны Node.js 22+ и BB 0.50+.

```sh
cd plugins/bb-jevstice
npm ci
npm run check
npm test
bb plugin build .
bb plugin install .
```

Jevstice использует ключ bb-jev через межплагинный RPC. В треде запустите
`bb jevstice status` и проверьте `keyConfigured: true`.

## Из треда BB

- Кнопка **Jev** в шапке треда включает диагностику без общего лимита запросов к судье.
  **Jev ✓** показывает включённый режим. Повторное нажатие выключает режим, а в дочернем
  треде унаследованный режим управляется из родительского. На узком экране действие в меню треда.
- В боковой карточке **Limits** строка **Jev** показывает баланс и общий счётчик `bb-jev`,
  включая новые запросы через мост Jevstice. Исторический счётчик `bb-jev` учитывает также
  проверки с недоступным судёй. Прошлые отдельные вызовы Jevstice в него не попадают.
- `bb jevstice on` включает текущий тред и его новых непосредственных детей. Предыдущие
  инструментальные события корневого треда не загружаются. После перезагрузки плагина
  включение нужно повторить. Сохранённая диагностика доступна через `status`.
- `bb jevstice status` показывает число попыток обращения к судье и журнал.
- Над полем ввода активного треда виден ход запроса и последний вердикт Jev.
- После завершения хода с наблюдаемой правкой BB автоматически проверяет дифф
  и доступный вывод тестов. Такая запись отмечается `automatic: true`.
- `bb jevstice off` прекращает расход и наблюдение. Штатные три квитанции Рундо
  обслуживает отдельный плагин bb-jev.
- Для нового сеанса провайдера BB добавляет 15 инструментов `jevstice_*`. Если провайдер
  уже запущен, вызовите проверку через `bb jevstice check jevstice_requirements '<JSON>'`.
- `python3 -m tools.rundo run <номер> --jevstice` включает диагностику и передаёт постановку
  задачи до создания дочерних тредов. Если режим уже включён кнопкой, новые треды обычного
  запуска Рундо наследуют его.

Зарегистрированные инструменты с префиксом `jevstice_`:

| Назначение | Суффиксы |
|---|---|
| Постановка и план | `triage`, `requirements`, `plan_review`, `reaim`, `course_check` |
| Проверка работы | `acceptance`, `review`, `issue`, `todo` |
| Проверка материала | `fact_check`, `search_relevance`, `text_review`, `anti_slop` |
| Посмотреть доказательство или спросить судью | `context`, `consult` |

События команд и файловых правок поступают из BB. Для чтения без текста, непрозрачного
инструмента или запуска без результата фиксируется недоступное наблюдение. Плагин читает
артефакты `local://NAME` из `tmp/jevstice/` рабочего дерева треда.

В BB используется обычный контроллер Jevstice. Нативный Linux-супервизор с рабочим процессом OMP
доступен в исходном архиве. Проверка его запуска на хосте с systemd выявила сбои.
