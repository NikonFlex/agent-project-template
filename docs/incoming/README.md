# Входящие документы

Документы от людей (ТЗ, переписка, заметки, расшифровки созвонов) — **как получены**.
Это не требования: канон — только то, что перенесено в [openspec/specs/](../../openspec/README.md).
Порядок работы — [docs/SPEC-DRIVEN.md](../SPEC-DRIVEN.md).

- Файл после приёма **не правится никогда**: номера его строк — адреса в строках источника
  требований. Новая редакция — новый файл с меньшим номером в «Источники и старшинство»
  `openspec/README.md`; строки, которые она меняет, переписываются в требованиях.
- Каждый файл записан в [index.yaml](index.yaml) с `sha256` и адресом оригинала, если
  документ выгружен по ссылке, и стоит строкой в «Источники и старшинство».
- Что из файла стало требованиями — `openspec/source-map.md` (пункт → спека) и
  `openspec/reverse-ledger.md` (строки, не ставшие требованиями); `tools/source_check.py`
  проверяет, что названа каждая непустая строка.
- Обычный поиск (`rg`) эту папку пропускает (`.rgignore`), чтобы входящие
  не читались как требования. Искать явно: `rg --no-ignore <слово> docs/incoming/`.
- Чужие документы, которые нельзя класть в git (PDF под копирайтом, презентации), —
  вне git; здесь — строка, где они лежат и почему их нет.
