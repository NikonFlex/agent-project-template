# Журнал решений

Значимые выборы: что решили, почему, что отбросили. Когда спросят «почему так, а не
иначе», ответ должен быть здесь, а не восстанавливаться по памяти.

Формат записи:

```
## ГГГГ-ММ-ДД — <решение>
**Статус:** принято / предложено / отменено
**Контекст:** что заставило выбирать
**Решение:** что выбрали
**Причина:** почему
**Альтернативы:** что отбросили и почему
```

## 2026-10-10 — Спеки в формате OpenSpec вместо своего формата в каталоге specs (tpl#29)
**Статус:** принято
**Контекст:** шаблон переводится на процесс из `sdd-process.md` (milestone SDD), проверенный
на работающем проекте: требование — проверяемая цепочка от строки источника до прогона.
**Решение:** `openspec/specs/<имя>/spec.md`, спеки двух типов (сущность, экран), строка
источника у каждого требования; форму проверяет `@fission-ai/openspec` 1.14.1 в строгом
режиме, остальное — `tools/spec_check.py`. Пометки истории (дельты, «подтвердил»,
`provisional`, «Открыто») убраны: спека — артефакт инженера, история — в коммите и задаче,
вопросы — таблица в `openspec/README.md`. Вместе с ними убраны прибор spec_audit и навык
«аудит спек»: сжимать стало нечего, а запрет истории проверяет `spec_check.py`.
**Причина:** строка источника проверяется прибором; история рядом с нормой путает агента.
**Альтернативы:** оставить свой формат и добавить строку источника — отказались: валидатор
OpenSpec и формат уже есть и проверены (правило 1); держать `spec_audit` — нечего мерить.
Версия валидатора закреплена: новая может поменять правила строгого режима.

## 2026-10-10 — Входящие без статусов разбора; покрытие — карта и реестр (tpl#30)
**Статус:** принято
**Контекст:** в прежнем порядке `index.yaml` хранил статус документа (`incoming → reviewed →
distilled`) и `distilled_into`. В процессе SDD то же видно точнее: `openspec/source-map.md`
(пункт → спека) и `openspec/reverse-ledger.md`, а `tools/source_check.py` проверяет, что
названа каждая непустая строка.
**Решение:** в индексе — путь, дата, откуда (`origin`), `sha256`; каждый документ — строкой в
«Источники и старшинство». Новая редакция — новый файл с меньшим номером.
**Причина:** два учёта одного и того же расходятся; построчное покрытие проверяется прибором,
статус — нет.
**Альтернативы:** держать статусы рядом с картой — второй источник правды без проверки.

## 2026-10-11 — Номер задачи из `git ticket`, проверки перед коммитом — git-хуком (tpl#33)
**Статус:** принято
**Контекст:** процесс SDD требует номер задачи в каждом коммите и одинаковые проверки перед
коммитом для Claude Code, Codex, Cursor и человека.
**Решение:** `git ticket <номер>` хранит задачу в git-каталоге клона или worktree; хук
`commit-msg` дописывает «Implements <префикс>#N»; CI проверяет все коммиты ветки (слияния и
«chore(backlog):» — без номера; до tpl#44 — «backlog:»). Хук `pre-commit` (`check.sh --quick`) — git-хук из
`templates/githooks/`, а не хук Claude Code: его видят все среды. В PR — «Implements», не
«Задача».
**Причина:** номер из имени ветки путали; хук одной среды не защищает остальные.
**Альтернативы:** номер из имени ветки — отказались по процессу; хуки в каждой среде отдельно —
три копии одной проверки.

## 2026-10-11 — AGENTS.md и сторожа для Claude Code, Codex и Cursor (tpl#34)
**Статус:** принято; отменяет «шаблон только под Claude Code» (tpl#2)
**Контекст:** в команде разработчики с разными средами; процесс SDD держит правила и сторожей
общими.
**Решение:** `AGENTS.md` — общие правила, `CLAUDE.md` импортирует его (`@AGENTS.md`,
code.claude.com/docs/en/memory). Правила по темам — `docs/agents/`, копии собирает
`tools/agent_rules.py`. Сторожа — `.agents/guards/guard.py`, входы: Claude Code PreToolUse
(код 2 / permissionDecision ask), Codex PreToolUse `.codex/hooks.json` (код 2) и execpolicy
`.codex/rules/default.rules` с `prompt` для записи в GitHub — «ask» из хука Codex не
поддерживает (openai/codex cc7ba33, pre_tool_use.rs), Cursor `.cursor/hooks.json`
(`{"permission": …}`, формат по вторичным источникам — [не проверено]). Проверки перед
коммитом — git-хук, общий для всех. Хук PreToolUse с `closing_words.py` влит в сторож.
**Причина:** одно правило — в одном месте; хук одной среды не защищает остальные.
**Альтернативы:** держать три копии правил и три набора хуков — расходятся; только правила
словами — агент их обходит, сторож нет.

## 2026-10-11 — Процесс SDD целиком: docs/shared/SDD.md, ΔP, описания вместо программ (tpl#35)
**Статус:** принято
**Контекст:** последняя задача milestone SDD — документы процесса и навыки.
**Решение:** прежний SPEC-DRIVEN.md → `docs/shared/SDD.md` (роли, этапы, конвейер, ΔP,
обратная связь, выкладка, метрики, «Что выполняется руками»); журнал решений и ΔP —
`docs/shared/product/`; проверенные факты о системе — `docs/architecture/`, гипотезы — `tmp/`.
Мост таблицы обратной связи, чат-бот, сборка описания продукта и пайплайн выкладки — только
описанием: они зависят от стека и сервисов проекта (решение хозяина 10.10). FPSR остаётся
метрикой рядом с метриками процесса. `/bootstrap` спрашивает: один репозиторий или рабочее
пространство, контуры, стенд, среды разработчиков.
**Причина:** процесс проверен на работающем проекте (слово хозяина 10.10); шаблон его повторяет.
**Альтернативы:** писать мост и бота в шаблоне — без сервисов проекта их нечем проверить.

## 2026-10-11 — Заголовок коммита по Conventional Commits 1.0.0 (tpl#44)
**Статус:** принято
**Контекст:** формата коммитов не было; номер задачи уже проверяли хук и CI.
**Решение:** `<тип>[(область)][!]: <описание>`, типы — `feat`, `fix`, `docs`, `refactor`, `perf`,
`test`, `build`, `ci`, `chore`, `style`, `revert` (Conventional Commits 1.0.0 и соглашение
Angular, [проверено: conventional-commits/conventionalcommits.org, content/v1.0.0/index.md]).
Тип и область — по-английски, описание — на рабочем языке. Учёт — `chore(backlog): …`. Проверяет
`tools/commit_check.py` в хуке `commit-msg` и в CI.
**Причина:** тип в заголовке делает историю читаемой и разбираемой программами; стандарт общий.
**Альтернативы:** commitlint — готовый линтер, но тянет Node в хук на каждый коммит, а хук у нас
уже есть; «классика git» без типов — не видно, что изменение делает; gitmoji — хуже грепается.

## 2026-10-11 — `backlog.py` и `fpsr.py` ходят в GitHub только через REST (tpl#47)
**Статус:** принято
**Контекст:** в облачной сессии GraphQL закрыт: `gh issue list`, `gh pr list`, `gh repo view`
отвечают 403, и `backlog.py sync/new/comment` не работал [проверено: запуск 11.10].
**Решение:** все вызовы — `gh api` REST: задачи и комментарии — двумя списками на репозиторий,
заведение и комментарий — `POST` с телом из файла, PR и их файлы — `repos/…/pulls`.
Репозиторий без `.backlog.json` — из адреса origin. Доска (Projects v2) — только GraphQL: где он
закрыт, колонка «Доска» — «—». `backlog.py` убран из исключений `ruff` и `jscpd`.
**Причина:** REST открыт и в облаке, и локально; одна дорога вместо двух.
**Альтернативы:** держать GraphQL и откатываться на REST при 403 — два кода на одно;
MCP-инструменты GitHub — есть только у агента, не у скрипта.

## 2026-10-11 — Ключи в коммитах ловит gitleaks в хуке и CI (tpl#48)
**Статус:** принято
**Контекст:** сторож не даёт прочитать `.env`, но ключ, вписанный в код или конфиг, уходил в
коммит; `ruff` (S105) ловит только присваивания с «password» в имени.
**Решение:** gitleaks 8.30.1 (MIT, релиз 21.02.2026 [проверено: proxy.golang.org, LICENSE в
модуле]). `tools/secret_scan.py`: хук `pre-commit` — `gitleaks git --staged`, CI — по
коммитам PR; исключения — `.gitleaks.toml` (стандартные правила плюс пути с причиной). Ставится
`go install` закреплённой версии (облако: github.com/releases закрыт, прокси Go открыт) или
архивом релиза со сверкой по контрольным суммам (CI). Самопроверка требует, чтобы ключи AWS,
OpenAI и Anthropic ловились своими правилами в индексе и в коммите.
**Причина:** готовый поиск с сотнями правил, один бинарь без Node и Docker, живой проект.
**Альтернативы:** trufflehog — сильнее проверкой ключей по сети, но тяжелее и для хука
медленнее; detect-secrets — Python, но правил меньше и нужен файл-база; своё сито как в
`backlog.py` — только несколько форм ключей.
