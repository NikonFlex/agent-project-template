# Файл задачи

Прочитать до правки файла задачи (Claude Code и Cursor подгружают сами). Когда что делать с задачами —
`AGENTS.md`, «Задачи»; устройство и образцы — `docs/examples/tasks/README.md`.

- Файл делится меткой — копировать посимвольно, не набирать:
  `<!-- ↓↓↓ ниже наше: скрипт эту часть не трогает ↓↓↓ -->`
  Выше метки — копия из GitHub, `sync` её перезаписывает: туда не писать.
- Низ: строка «Локальный повтор», «Чем возобновлять» (первый шаг для следующей сессии),
  «Что установлено» (проверенное, с файлом и датой), «Что опровергнуто», «Тупики», «Ход
  работы», «Что осталось» (недоделанное — раздел появляется, когда оно есть). Писать то, что
  верно сейчас, в настоящем времени, для читателя без разговора; даты — только абсолютные;
  свою прежнюю ошибку заменить на месте, без опровержения ниже.
- **«Локальный повтор»** — первая строка низа, заполняется в начале работы, до PR:
  `Локальный повтор: воспроизведён — тест: <какой>` (или `— контур: <что прогнали>`,
  `— экран: <что увидели>`), либо `невозможен локально / не требуется / не бага — <причина>`.
  Без неё сторож не даёт создать PR; классификация не восстанавливается задним числом.
- **Своё дерево до первой правки**: `git worktree add ../<репо>-<номер> -b agent/<номер>-<имя>`
  и `git ticket <номер>` в нём — хук `commit-msg` допишет «Implements <префикс>#<номер>» в
  коммит без ссылки. Номер не берётся из имени ветки. Из дерева не править другие клоны.
- **Коммит** — заголовок по Conventional Commits 1.0.0: `<тип>[(область)][!]: <описание>`.
  Типы: `feat` — новое поведение, `fix` — исправление, `docs`, `refactor`, `perf`, `test`,
  `build`, `ci`, `chore`, `style`, `revert`. Область — имя спеки или части репо
  (`feat(assignment): …`, `ci: …`); `!` — несовместимое изменение. Тип и область — по-английски,
  описание и тело — на рабочем языке: что и почему, а не как. Подвал — trailers, среди них
  «Implements <префикс>#N» (дописывает хук). Коммит учёта (копии задач, журнал) —
  `chore(backlog): …`, без номера задачи; так же без номера — обновления Dependabot
  `build(deps): …`. Слово `fix` в типе задачу не закрывает; рядом с
  номером (`fix #12`) — закрывает, и его остановят хук и CI. Проверка — `tools/commit_check.py`
  (хук `commit-msg` и CI).
- **Закрытие** — три отметки в низу, каждую ставит тот, кто проверял, с датой и строкой о
  том, что прошло: «проверено локально», «проверено на dev», «проверено на проде» (прод
  заморожен — строка, что прод получит изменение после разморозки). Сводка из пяти пунктов
  комментарием в задачу: что просили; что изменилось в поведении; как проверить самому; чего
  из просьбы не сделано; где это сейчас. Статус требований задачи в таблице требований — ✅ с
  номером задачи. Закрывает хозяин или приёмщик после проверки на работающей системе, не
  слияние.
- Черновик `draft-<имя>.md`: первая строка `# Название`, строка `Milestone: <имя>`, если
  задача входит в milestone, дальше что сделать, «Готово, когда» и, если у работы есть
  промежуточный результат, «Датчик:» — каким числом его видно.
- **Задача называет требования**, которые закрывает:
  `` `openspec/specs/<спека>/spec.md` — «<заголовок>», «<заголовок>» ``. Задача без требований
  (документы, доступы, настройки) говорит это строкой «без сценария — <причина>». Проверка —
  `python3 tools/task_links.py`: ссылка на несуществующее требование — ошибка; требования без
  задачи и открытые задачи без ссылки — сведения.
- **До кода — сверка с онтологией**: сущность, роль, кабинет или путь, которые задача
  собирается создать, уже есть или нет. Вторая сущность или второй путь для той же задачи
  пользователя — только пунктом ΔP или решением продакта.
- **«Готово, когда» — проверяемо**: наблюдаемый результат на рабочем контуре, который можно
  измерить; каждый пункт — команда или наблюдение с ясным «да/нет». Критерий с замером — после
  того, как замер получен хотя бы раз; неясно, возможен ли замер, — сначала задача на прибор.
  Размытая цель («удобнее», «быстрее») — до начала превратить в измеримую или спросить хозяина.
- **Название — работа, а не находка.** Замеры и разбор — в теле. Замер показал, что постановка
  неверна или неполна, — правится тело задачи, а не пишется комментарий.
- PR, который не меняет термины, сущности, связи, роли и пути, говорит это строкой «Описание
  продукта не затронуто»; который меняет — правит спеку в том же PR.
- **«Первый промпт»** — раздел низа при закрытии: `да` — сделано без уточнений от хозяина по
  сути задачи (согласие на слияние не в счёт); `нет — <почему>` — какое противоречие, дыра
  или неясная цель потребовали вопроса и что исправлено в среде. Оценку — хозяину одной
  строкой: её ставит сам агент, и хозяин может её поправить. Долю считает
  `python3 tools/fpsr.py`, разбор причин — `/fpsr` (FPSR — `docs/WHY.md`).
- Находка по существующей задаче — в низ её файла, а не в новую задачу.
