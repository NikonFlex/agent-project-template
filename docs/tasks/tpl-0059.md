## Описание из трекера

Без сценария — модули обвязки, включаются в `/bootstrap` по желанию; поведения продукта не
меняют.

Перенести модули, проверенные в проекте из шаблона, обобщив имена людей в места
`{{продакт}}`, `{{инженер}}` и т. п.; `/bootstrap` спрашивает, какие включить.

Что сделать:

1. **Telegram**: `tools/tg_*` (отправка, разбор входящих, выгрузка, уведомления, пинг),
   `.github/workflows/tg-notify.yml` и `tg-pull.yml`, навыки `/inbox` и `/questions`,
   настройка пинга и хуки Claude Code `Stop` и `Notification`.
2. **Передача наружу**: `tools/handover_check.py` (ключи — gitleaks и значения из `.env`,
   пароли, задачи, журнал, исходники), навык `/handover`, скелет
   `docs/agents/protection.md` и его копии правил (`tools/agent_rules.py`).
3. **Проверка экрана (braille)**: модуль из форка `blurman-ai/agent-braille` — сохранить
   LICENSE и NOTICE (Apache-2.0) и пометку о наших изменениях; отвязать от конкретного сайта
   (адрес API агента, шаблоны страниц — в настройку); правило `.claude/rules/screens.md`,
   тесты.
4. Сбор описания продукта в Google Drive — позже, отдельной задачей после обобщения.

Готово, когда:

- каждый модуль включается и выключается в `/bootstrap`, выключенный не оставляет файлов и
  проверок;
- самопроверки модулей зелёные; `handover_check.py --selftest` ловит подложенный ключ;
  braille проходит свои тесты на примере страницы из шаблона;
- `python3 tools/harness.py` — «обвязка в порядке»; в диффе нет имён проекта, из которого
  перенесено (`handover_check.py` и просмотр глазами).
