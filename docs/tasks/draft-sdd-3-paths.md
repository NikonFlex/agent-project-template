# SDD 3. Пользовательские пути и связь требований с задачами

Milestone: SDD

Разделы 9, 10 («Постановка») `sdd-process.md`.

Что сделать:

1. `openspec/paths/`: README «экран → адрес → пути», шаблон `<роль>-<NN>-<слово>.md`, `not-in-paths.md` с классами.
2. Прибор путей: форма; названные требования существуют; каждое требование в пути или в реестре.
3. Задача называет требования (`` `openspec/specs/<спека>/spec.md` — «<заголовок>» ``) или «без сценария — причина»; черновик задачи и `.claude/rules/tasks.md`.
4. Прибор «требование ↔ задача» по `docs/tasks/`.

Готово, когда:

- `--selftest` падает на: требование в пути не существует; требование не названо ни в пути, ни в реестре; задача ссылается на несуществующее требование;
- пример пути в `docs/examples/` проходит;
- приборы в `tools/check.sh`.
