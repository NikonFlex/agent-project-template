## Описание из трекера

Хозяин хочет, чтобы Claude сам предлагал сжать контекст (`/compact`) и открыть новый чат,
когда контекст заполнен: крупную задачу лучше начинать с почти пустым контекстом.

Что сделать:
- хук `UserPromptSubmit` считает занятый контекст по журналу сессии (`transcript_path`,
  `usage` последнего ответа) и при порогах добавляет Claude короткую строку;
- пороги и размер окна — в конфиге, не в коде;
- в `CLAUDE.md` — что делать на каждом пороге: когда предлагать новый чат, когда `/compact`,
  и что перед этим обновить «Чем возобновлять».

Готово, когда:
- на подложенном журнале сессии хук молчит ниже порога и печатает строку выше него;
- в живой сессии строка доходит до Claude;
- самопроверка хука в CI.

## Что установлено

- Готового нет: в хук заполненность контекста не передаётся (есть только у statusline:
  `context_window.used_percentage`), хук не может вызвать `/compact`
  `[проверено: statusline.md, hooks.md; поиск — feature request на claudeissues.com, не проверено]`.
- В журнале сессии у ответа `message.usage`; занято = `input_tokens +
  cache_creation_input_tokens + cache_read_input_tokens` — та же формула, что у
  `used_percentage` в statusline `[проверено: statusline.md + журнал этой сессии]`.
  Ответы субагентов помечены `isSidechain` — не считаются.
- `claude_hooks.py context` (UserPromptSubmit): последний ответ основной сессии из хвоста
  журнала (4 МБ), окно и пороги — `.claude/context.json` (new_chat / compact / urgent),
  ниже порогов — тишина; больше 100% — подсказка поправить окно.
  Самопроверка ловит выключенный отсев субагентов `[проверено: запуск 06.10]`.
- На журнале этой сессии: 327k из 200k → «urgent» и подсказка про окно `[проверено]`.
- Живьём: `claude -p` + `--resume` той же сессии при порогах 1/2/3 % — Claude процитировал
  «Контекст: 19% (37k из 200k), порог «urgent» (3%)…» `[проверено: 06.10]`. На первом
  сообщении сессии ответов в журнале ещё нет — хук молчит.
- `CLAUDE.md`, «Контекст»: что делать на каждом пороге; числа — только в конфиге.
  `CLAUDE.md` — 198 строк (сжаты «Журнал», правила 2, 5, 6).

- **Решение хозяина 06.10:** окно 1 000 000, пороги 50 / 70 / 85 %. Оставлены в процентах:
  в токенах это те же 500k / 700k / 850k, выигрыша нет.
- Процент — вниз (`100 * used // window`), не `round`: при `round` 499k давали «50%» и порог
  срабатывал раньше; самопроверка ловит возврат к `round` (случай 79k при 40% от 200k)
