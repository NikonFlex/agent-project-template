## Описание из трекера

Без сценария — процесс работы с задачами, поведения продукта не меняет.

Сейчас в шаблоне задачу закрывает только хозяин после проверки. Решение хозяина 19.11.2026:
перенести порядок, проверенный в проекте из шаблона, — задачу закрывает слияние PR с
`Closes #N` в теле, полный набор проверок идёт после слияния, красный результат переоткрывает
задачу; перед push — проверка чистого контура по своему диффу.

Что сделать:

1. `tools/pr_link.py`: в теле PR — `Closes #N` или `Part of #N`; проверка `pr-link` в CI.
2. `tools/post_merge.py` и `.github/workflows/post-merge.yml`: полный набор после слияния,
   комментарий в задачу с исходами, красный — переоткрытие задачи.
3. `.github/workflows/check.yml`: быстрый набор `fast` и `pr-link` на PR, автослияние по метке
   `automerge`; `tools/quick_scope.sh`, очередь хуков `tools/hook_lock.sh`, `pre-commit`.
4. Навык `clean-contour-check` и `docs/clean-contour.md` — с файлами LICENSE и NOTICE
   (Apache-2.0) источника; строка «Чистый контур:» в задаче, `task_links.py` её проверяет;
   сторож push без этой строки при изменённом коде.
5. `docs/agents/tasks.md` (PR, чистый контур, закрытие), `AGENTS.md`, `docs/decisions.md` —
   решение со смены порядка, `docs/WHY.md` — почему.

Готово, когда:

- `pr_link.py --selftest` и `post_merge.py --selftest` зелёные и краснеют на откаченном
  исправлении; сторож останавливает push без строки «Чистый контур:» (самопроверка
  `guard.py`);
- на временном репозитории из шаблона PR с `Closes #N` сливается по зелёным `fast` и
  `pr-link` и закрывает задачу [проверка на GitHub — по «да» хозяина];
- `python3 tools/harness.py` — «обвязка в порядке»; в диффе нет имён проекта, из которого
  перенесено (проверка перед push и просмотр глазами).
