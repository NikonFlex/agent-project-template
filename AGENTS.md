## Роли

Продакт — замысел и наблюдаемый результат: PRD, пункты ΔP, ответы на вопросы. Инженер — путь
от замысла до работающего продукта: спеки, онтология, задачи, сценарии, статус требований;
спеку продакт не согласует. Агенты — код и тесты по задаче, записи в файле задачи. Агент сам
решает всё, что не меняет наблюдаемое поведение; что меняет — вопрос продакту
(`openspec/README.md`, «Вопросы продакту»). {{Чьи требования не отменяются молчанием другого.}}

## Ход работы

- **Ход заканчивается отчётом, а не вопросом.** Вопрос — только о том, что требует приказа
  (новая задача, приоритет, исполнитель, PR, push, прод), или о необратимом: один, с причиной.
- **Лучший вариант — решение агента**: объявить его отдельной строкой и сделать.
- **Сначала ищем готовое** (GitHub, реестры пакетов, статьи): живая ли репа, лицензия,
  работает ли заявленное. Результат поиска — в задачу; «ничего не найдено» — тоже запись.
- **Факты — из первоисточника** (документация, код, запуск), не по памяти. В `docs/` факт
  помечен `[проверено]` (чем) или `[не проверено]`; гипотезы — в `tmp/` (не в git).
- **«Работает», «готово» — только после запуска.** Не запускал — так и сказать, с причиной.
  Оговорка вместо проверки («пока», «упрощённо», «заглушка») — не ответ.
- **Результат смотреть глазами** тем же путём, каким смотрит человек.
- **У проверки есть случай, на котором она падает**: написал тест — сломать код, увидеть
  красное; откатить обратной правкой.
- **Три неудачные попытки — стоп**: четвёртую не делать. Первой строкой — что чинил, три
  попытки с результатом, какая дыра в коде, доке или спеке и как её закрыть. Попытки — в
  «Тупики» задачи.
- **Путаница — чинить источник, а не ответ**: знание — в репо, неверный источник — исправить.
- **Сначала кратчайший путь** до работающего целого; улучшения — после.
- Задача с проверяемым «Готово, когда» — до конца, без промежуточных отчётов.

## Задачи

Задачи GitHub — копией в `docs/tasks/<префикс>-0012.md` (префикс — `.backlog.json`), скрипт
`tools/backlog.py`. Устройство файла задачи и порядок — [docs/agents/tasks.md](docs/agents/tasks.md).

1. **Задача — до работы, по слову хозяина.** Сначала `grep -ri <слово> docs/tasks/`. Нашлась —
   работать по ней. Нет — спросить одной строкой «Завожу задачу „<название>“?». «Да» —
   черновик `docs/tasks/draft-<имя>.md` и `python3 tools/backlog.py new <черновик> --confirm`.
   Находка по ходу (баг рядом, идея) — в «Что осталось» и хозяину одной строкой.
2. **Начиная** — `python3 tools/backlog.py resume <номер>`, низ файла; своё дерево
   (`git worktree`) и `git ticket <номер>`; строка «Локальный повтор» — до кода.
3. **По ходу** — дописывать низ файла задачи; прерываясь — «Чем возобновлять».
4. **Коммит** — `<тип>[(область)]: <описание>` по Conventional Commits (`docs/agents/tasks.md`);
   хук `commit-msg` проверяет форму и дописывает «Implements <префикс>#N»; **никогда close,
   fix, resolve рядом с номером** — задачу закрывает человек (`tools/closing_words.py`).
5. **Сдача** — PR с меткой `automerge`, в описании «Implements <префикс>#N» и «Описание продукта
   не затронуто» либо правка спеки. CI гоняет `sh tools/check.sh`, проверяет номера в
   коммитах и закрывающие слова и сливает сам. Красный CI — чинить в том же PR.
6. **Сделано** — сводка из пяти пунктов комментарием, «Первый промпт» в низ; закрывает
   хозяин или приёмщик после проверки на работающей системе.

## Границы действий

Читать, измерять, диагностировать — свободно. Изменение состояния систем — готовится,
показывается с откатом и применяется по «да» человека на конкретное действие. Сторожа
(`.agents/guards/`) перехватывают команды до выполнения во всех трёх средах:

| Сторож | Что останавливает |
|---|---|
| запись в GitHub | `gh issue/pr/project …`, `git push` без «да» |
| прод | запись на прод-контур без «да» |
| локальный повтор | `gh pr create`, пока в задаче нет строки «Локальный повтор» |
| квитанция | push, где гейт включён, без квитанции живого прогона на том же дереве кода |
| секреты | чтение `.env` и других файлов с ключами |
| закрывающие слова | close, fix, resolve рядом с номером задачи |

Git-хуки (`templates/githooks/`, `sh tools/install_hooks.sh` после клона): `pre-commit` —
`check.sh --quick`, `commit-msg` — номер задачи. Состояние обвязки и все контрольные случаи
без сети — `python3 tools/harness.py`.

## Ключи и деньги

- Ключи — только в `.env` (в `.gitignore`; в git — `.env.example` без значений). Ключ, попавший
  в код, задачу, коммит, журнал или чат, — скомпрометирован: сказать хозяину сразу.
- Платный запрос — сначала сказать, сколько их будет, и прогнать на одном-двух. Тесты в
  платный API не ходят: вызов подменяется заглушкой.
