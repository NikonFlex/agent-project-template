Репозиторий только что создан из шаблона. В `AGENTS.md`, `README.md`, `docs/dev-plan.md`,
`openspec/README.md` и правилах стоят места `{{…}}`; в `docs/tasks/` лежат задачи самого
шаблона (префикс `tpl`). Цель — к концу захода проект живёт по правилам `AGENTS.md` и
`docs/shared/SDD.md`, проверки проходят, мест `{{…}}` не осталось, первая задача заведена.

## 1. Проверить окружение (параллельно)

- `git remote -v` — есть ли репозиторий на GitHub. Нет — спросить хозяина, создать ли
  (`gh repo create <имя> --private --source=. --push`); это действие наружу.
- `gh auth status`, `python3 --version`, `python3 -c "import yaml"`, `node --version`,
  для Python-стека — `ruff --version`, `pytest --version`, `python3 -m pytest --testmon --version`
  (`pip install pytest-testmon` — хук перед коммитом гоняет только затронутые тесты).
- Метка для автомерджа: `gh label create automerge --description "CI сольёт PR после зелёного
  полного прогона"` — это действие наружу, вместе с созданием репозитория.
  Чего нет — сказать, чем поставить; `pyyaml` — `pip install -r tools/requirements.txt`.

## 2. Расспросить хозяина — одним пакетом

Вопросы «Старт проекта» из `docs/shared/SDD.md` и вдобавок:

- название проекта и одна фраза, что строим;
- стек: язык (по умолчанию Python), фреймворк, где работает; чем проверять (линтер, тесты) — предложить
  принятые для стека, с версиями, найденными поиском, а не по памяти (правило 1);
- префикс задач (две-три латинские буквы, например `ab` → `ab#12`, `ab-0012.md`);
- рабочий язык документов;
- кто продакт (заказчик) и кто инженер; чьё слово окончательное, если требования идут от
  нескольких людей (`AGENTS.md`, «Роли»);
- **один репозиторий или рабочее пространство**: продукт в одном репозитории (по умолчанию)
  или в нескольких (бэкенд, фронтенд, инфраструктура). Во втором случае этот репозиторий —
  рабочее пространство: спеки, задачи, правила и сторожа здесь, клоны продукта — в `repos/`
  (в `.gitignore`), задачи всех репозиториев — в `docs/tasks/` с префиксом репозитория;
- **контуры**: есть ли рабочий контур (dev) и прод, как туда выкладывается, где `/health`;
  шаблоны команд, которые пишут на прод, — в `"prod"` `.agents/guards/config.json`;
- **стенд для сценариев**: адрес API, база, compose, подставной провайдер модели —
  `tests/scenarios/stand.json` из `stand.example.json`; включать ли гейт квитанции перед
  push (`"gated"` в `tools/receipt.json`, по умолчанию выключен, пока нет стенда);
- в каких средах работают разработчики (Claude Code, Codex, Cursor) — всем им после клона
  `sh tools/install_hooks.sh`; в Codex — доверить хуки проекта `.codex/`;
- какие документы уже есть — прислать как есть;
- как запускать проект, где смотреть логи — в «Команды» `AGENTS.md`, каждое одной командой;
- дополнительные гейты для Python (по умолчанию — нет, пока нет кода): порог покрытия
  (`pytest-cov`), мутационное тестирование (`mutmut`), сценарии из «Критериев приёмки»
  спек (`pytest-bdd`). Взятое — в `tools/check.sh`, версии — поиском, не по памяти.

На каждый вопрос — предложение по умолчанию, чтобы можно было ответить «да».

## 3. Убрать следы шаблона

- `docs/tasks/` — удалить `tpl-*.md`, `INDEX.md`, `REVIEW.md`.
- `.backlog.json` — новый префикс.
- `docs/journal/JOURNAL.md` и `docs/decisions.md` — оставить шапку и формат, записи шаблона
  удалить. `docs/journal/INSIGHTS.md` — оставить: это общие уроки. `docs/examples/`,
  `docs/WHY.md` — оставить: образцы и объяснения не про шаблон, а про работу.
- `README.md` — переписать под проект (что это, как запустить), про шаблон — одна строка.

## 4. Заполнить места `{{…}}`

`grep -rn '{{' --exclude-dir=.git --exclude-dir=skills --exclude-dir=tools .` — пройти все
(в навыках и скриптах `{{` стоит законно; в `docs/agents/` — нет, после правки —
`python3 tools/agent_rules.py --write`). Что хозяин не знает — разумное
умолчание, записанное строкой в `docs/decisions.md`, а не `{{…}}`.
Схему в `AGENTS.md` на первом заходе можно оставить одним абзацем — она рисуется,
когда появится замысел.

## 5. Подстроить проверки под стек

Стек по умолчанию — Python: `ruff.toml`, ruff и pytest в `tools/check.sh` (его запускают CI
и хук перед коммитом), Python-блок в `.gitignore`.

- **Python** — `ruff check .` и `pytest` уже стоят. Проверить, что оба проходят; `pytest`
  с кодом 5 («тестов нет») в CI не ошибка. Зависимости проекта — `requirements.txt`,
  CI его ставит, если файл есть.
- **Другой язык** — заменить на линтер и тесты стека:
  - `tools/check.sh` — линтер и тесты стека вместо ruff и pytest;
  - `AGENTS.md`, «Стек» в шапке;
  - `docs/agents/code.md` и `TOPICS` в `tools/agent_rules.py` — пути под расширения стека,
    затем `python3 tools/agent_rules.py --write`; последний пункт — чем в этом
    языке проверяются правила (сложность, enum, импорт без псевдонимов);
  - `.github/workflows/check.yml` — шаг «Зависимости»;
  - `.gitignore` — Python-блок на каталоги сборки и окружения стека;
  - `ruff.toml` — удалить, если Python в проекте нет (скрипты в `tools/` линтер не требуют).
- `.jscpd.json` — что не проверять (сгенерированный код, зависимости).
- `tools/context_check.json` — если документы пишут пути коротко, от папки пакета
  (`render/<файл>` вместо `<пакет>/render/<файл>`), — папка пакета в `bases`; журнал
  решений и обзоры чужих репозиториев — в `skip_docs`; DOI и похожее — в `ignore_patterns`.

Проверку подключать, только когда она поймала подложенный дефект.

Если в репозиторий принесли готовый код: ключ API прямо в коде — перенести в `.env`,
в коде читать из переменной окружения, имя — в `.env.example`; сказать хозяину, что ключ
уже был в git и его надо заменить на сайте сервиса. `git ls-files .env outputs/` — что
закоммичено, убрать `git rm --cached`, файлы на диске не трогать.

## 6. Входящие и первые спеки

Документы хозяина — в `docs/incoming/` как получены, с записью в `index.yaml` (sha256 —
`sha256sum`) и строкой в «Источники и старшинство» `openspec/README.md`. Дальше — конвейер
из `docs/shared/SDD.md`: сущности и экраны, первые спеки в формате `openspec/README.md`,
вопросы продакту — в таблицу. Нет документов — записать разговор с продактом как входящий
документ и брать строки источника из него.

## 7. Проверить и зафиксировать

```
grep -rn '{{' --exclude-dir=.git --exclude-dir=skills --exclude-dir=tools .    # пусто
ruff check .                     # или линтер стека
pytest                           # или тесты стека
python3 tools/backlog.py --selftest
sh tools/install_hooks.sh        # git-хуки pre-commit, commit-msg и `git ticket`
sh tools/check.sh                # всё сразу: самопроверки, приборы спек, openspec validate, jscpd
python3 tools/harness.py         # хуки, сторожа в трёх средах, самопроверки — «обвязка в порядке»
```

Первая задача — «Заведение проекта» через `docs/tasks/draft-bootstrap.md` и
`backlog.py new … --confirm`; в её низ — что спросили, что решили, что осталось.
Коммит и пуш. CI на GitHub — дождаться зелёного.

## Отчёт хозяину

Что заполнено, какие умолчания выбраны сами (каждое — строкой), какие вопросы остались
открытыми, первый шаг по проекту.
