# Приёмка задач

Требование закрывает проверка на рабочем контуре, а не зелёный CI и не прочитанный код
(`docs/SPEC-DRIVEN.md`, «Сценарий до кода, проверка на контуре, статус»).

## Что проверять

1. Курсор прошлого прогона — `docs/shared/acceptance/cursor.json`: коммиты репозиториев
   продукта и время. Нет файла — первый прогон: курсор — последняя неделя.
2. Коммит, который сейчас на рабочем контуре, — из `/health` контура (отдаёт коммит образа).
3. PR, слитые между курсором и этим коммитом, и задачи, закрытые после курсора другими
   людьми. Задача PR — по «Implements <префикс>#N» в описании и по номерам в коммитах.

## Как

Критерии — чекбоксы и «Готово, когда» задачи, требования, которые она называет. Каждый —
на контуре: API — запросом, экран — браузером (playwright), данные — запросом к базе только
на чтение. Учётные записи проверки — свои, с меткой, после прогона удаляются. Дополнительно
прочитать дифф PR: корректность, контракт с другой стороной, тест без отрицательного случая.

| Исход | Действие |
|---|---|
| все критерии подтверждены | сводка из пяти пунктов комментарием (`.claude/rules/tasks.md`, «Закрытие»); закрыть — если хозяин разрешил приёмщику закрывать, иначе одной строкой хозяину |
| критерий не выполнен или не проверяется | комментарий «критерий → что увидел → как повторить», назначить автора PR; закрытую задачу переоткрыть |
| не выполнен, правка простая | исправить самому — в файлах того же PR, до 30 строк, без миграции и смены контракта, с тестом, падающим до правки; после выкладки проверить снова |
| нужен выбор продукта | комментарий с вопросом, задача остаётся открытой; вопрос — в «Вопросы продакту» |
| критериев нет | в отчёт «нечего принимать», трекер не трогать |

Комментарий, закрытие, переоткрытие — запись в трекер: показать хозяину команду и ждать «да»,
если он не разрешил приёмку целиком.

## Итог

Отчёт — `docs/shared/acceptance/<ГГГГ-ММ-ДД>.md`: закрыто, возвращено (кому, какой
критерий), поправлено, ждёт решения, пропущено и почему. Курсор обновить. Статусы требований —
`python3 tools/req_status.py --write` после записи прогона или вручную со свидетельством.

Хозяину — счёт: заведено и закрыто за сессию, открыто всего.
